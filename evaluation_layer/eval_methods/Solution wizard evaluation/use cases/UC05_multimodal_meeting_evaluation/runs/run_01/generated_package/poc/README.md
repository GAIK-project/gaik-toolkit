# AI-Assisted Meeting Record Generator -- Proof of Concept

Generated by GAIK Solution Configuration Wizard V2.

---

## What this PoC does

Combine meeting audio recordings, agenda documents, and participant lists into a structured, evidence-cited meeting record capturing decisions, actions, and unresolved issues.

---

## Prerequisites

- Python 3.11+
- GAIK toolkit: `pip install -r requirements.txt`
- API credentials (see `.env.example`)

---

## Setup

```bash
# 1. Install dependencies
pip install -r requirements.txt

# 2. Set up credentials
cp .env.example .env
# Edit .env and fill in your Azure OpenAI / OpenAI API key
```

## Running the PoC

This pipeline takes one **bundle manifest** describing a single meeting -- a JSON
file that points to the meeting recording, the agenda PDF, and the participant list:

```bash
python run_poc.py --input /path/to/poc_input_bundle.json
```

The manifest must look like:

```json
{
  "inputs": {
    "meeting_audio": "input/meeting.wav",
    "agenda_pdf": "input/agenda.pdf",
    "participant_list": "input/participants.json"
  },
  "output": {"directory": "output", "filename": "meeting_record.json", "format": "json"}
}
```

All three input paths are resolved **relative to the manifest's own directory**, not
the current working directory. Results are written to `output/`.

This PoC uses a **self-hosted Whisper endpoint** for transcription (see
`.env.example` for `LOCAL_TRANSCRIBER_API_BASE` / `LOCAL_TRANSCRIBER_API_KEY`) --
this keeps meeting audio on your own infrastructure and gives per-segment
timestamps for audio citations.

---

## Input

- Meeting audio (English, `.wav`)
- Agenda document (`.pdf`, text-layer -- not scanned/image-only)
- Participant list (`.json`, list of `{name, role}`)

The pipeline transcribes the audio (with timestamps), parses the agenda (with
page markers), and combines both with the participant list for extraction.

---

## Expected output

A single JSON object matching the `MeetingRecord` schema: `meeting_id`, `title`,
`meeting_date`, `start_time`, `end_time`, `participants`, `topics`, `decisions`,
`action_items`, `unresolved_issues`, `conflicts`, `review_status` (starts as
`pending_review`). Every decision/action/unresolved-issue/conflict carries at
least one citation (`file_name|start_timestamp|end_timestamp` for audio,
`file_name|page_number` for the agenda).

Written to `output/<filename from the bundle manifest>` (e.g. `output/meeting_record.json`).
A `validation.json` (LLMJudge hallucination report) is written alongside it.
