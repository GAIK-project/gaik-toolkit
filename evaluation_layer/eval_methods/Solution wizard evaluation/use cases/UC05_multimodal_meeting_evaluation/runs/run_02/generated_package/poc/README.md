# AI-Supported Meeting Record Generation -- Proof of Concept

Generated by GAIK Solution Configuration Wizard V2.

---

## What this PoC does

Combines a meeting audio recording, the agenda document, and the participant list to produce a structured, evidence-cited meeting record capturing decisions, actions, and unresolved issues for project-manager review.

---

## Prerequisites

- Python 3.11+
- GAIK toolkit: `pip install -r requirements.txt`
- API credentials (see `.env.example`)

## Running the PoC

This PoC reads a fixed **input bundle manifest** (a JSON file) rather than auto-discovering
files in `sample_input/`. The bundle references the three source files for one meeting:

```bash
python run_poc.py --input path/to/poc_input_bundle.json
```

The bundle looks like this (paths are resolved relative to the bundle file's own directory):

```json
{
  "meeting_id": "NIMBUS-PRR-2026-09-17",
  "inputs": {
    "meeting_audio": "input/project_nimbus_meeting.wav",
    "agenda_pdf": "input/project_nimbus_agenda.pdf",
    "participant_list": "input/project_nimbus_participants.json"
  },
  "output": {"directory": "output", "filename": "meeting_record.json"}
}
```

Results are written to `output/<filename>` (default `output/meeting_record.json`), plus
`output/validation.json` (the LLMJudge hallucination pre-screen report).

You also need a **self-hosted Whisper endpoint** for transcription (set
`LOCAL_TRANSCRIBER_API_BASE` / `LOCAL_TRANSCRIBER_API_KEY` in `.env`) -- audio citations
require per-segment timestamps, which the hosted transcription models do not return.

---

## Input

Three files per meeting, referenced by the input bundle manifest:

- **Meeting audio recording** (`.wav`) -- transcribed with per-segment timestamps for
  citation evidence.
- **Agenda PDF** -- a native-text (non-scanned) document parsed with page markers so
  agenda-sourced facts can be cited by page number. It records *proposed* items only;
  the spoken meeting is authoritative for what was actually decided.
- **Participant list** (`.json`) -- `{name, role}` pairs used directly (no parsing
  component); the extracted record's `participants` field is filled deterministically
  from this file rather than from the LLM's transcription.

---

## Expected output

A single JSON meeting record (`schemas/output_schema.py` / class `MeetingRecord_Extraction`)
with: `meeting_id`, `title`, `meeting_date`, `start_time`, `end_time`, `participants`,
`topics`, `decisions`, `action_items`, `unresolved_issues`, `conflicts`, `review_status`
(always `"pending_review"` in this PoC). Every decision, action item, unresolved issue,
and conflict carries at least one pipe-delimited citation
(`file_name|start_timestamp|end_timestamp` for audio, `file_name|page_number` for the
agenda). Owners/due dates the meeting did not explicitly state are `null`, with an
`uncertainty_reason` explaining why.

Written to `output/meeting_record.json` (or the filename given in the input bundle).
