# Finnish Voice Fault Reporting — Maintenance Ticket Generator
## Proof of Concept

Generated by GAIK Solution Configuration Wizard V2.

---

## What this PoC does

Field technicians record a short Finnish voice message describing a facility fault —
what is broken, where it is, and how urgent it is. The pipeline:

1. Transcribes the Finnish audio using `gpt-4o-transcribe` with Finnish-tuned enhancement.
2. Extracts nine structured fields from the transcript using `gpt-5.4` and the approved
   `MaintenanceTicket` schema.
3. Runs an `LLMJudge` hallucination check — every extracted field is verified against the
   source transcript. Any value not grounded in the audio is flagged.
4. Saves the ticket as JSON in `output/`. A human supervisor reviews and approves before
   any transfer to the maintenance management system.

**Important:** raw audio is not retained after processing. The approved ticket JSON
(or the PoC output JSON) may be retained.

## Input

Place a Finnish voice recording in `sample_input/`. Supported formats: `.wav`, `.mp3`, `.m4a`.

The recording should contain a technician describing:
- the fault (what is broken or wrong)
- the location (building, floor, room, zone, etc.)
- the urgency (kiireellinen / medium / low)
- optionally: asset identifier, observation date/time, and any immediate actions taken

Audio cannot be synthesised automatically — a real recording is required.

---

## Running the PoC

```bash
# Default: picks up the first audio file found in sample_input/
python run_poc.py

# Specify a file directly
python run_poc.py --input path/to/recording.wav
```

Results are written to `output/`.

---

## Expected output

A JSON file written to `output/<input_stem>_ticket.json` with these nine fields:

| Field | Type | Required |
|---|---|---|
| `reporter_name` | string or null | Optional |
| `asset_identifier` | string or null | Optional |
| `location` | string or null | **Required** — null + flagged if not stated |
| `fault_description` | string or null | **Required** — null + flagged if not stated |
| `urgency` | `"low"` / `"medium"` / `"high"` or null | **Required** — null + flagged if not stated or unsupported |
| `observation_date` | YYYY-MM-DD string or null | Optional |
| `observation_time` | HH:MM string or null | Optional |
| `actions_taken` | list of strings or null | Optional |
| `uncertain_fields` | list of field names or null | Lists any fields that could not be extracted |

A `_validation.json` file is also written alongside the ticket with the LLMJudge
hallucination-check results.

A `_transcript.txt` file is written with the enhanced Finnish transcript.

## Adjusting the PoC

| What to change | Which file |
|---|---|
| Extraction instructions (field descriptions, Finnish cues, handling rules) | `prompts/extraction_requirements.md` |
| Model or temperature | `config.yaml` |
| Schema field types or descriptions | `schemas/output_schema.py` |
| Evaluation metrics | `evals/run_basic_eval.py` |

If you edit `prompts/extraction_requirements.md`, the pipeline detects the change on the
next run and regenerates the schema automatically.

## Running the basic evaluation

```bash
python evals/run_basic_eval.py
```

Requires ground-truth JSON files in `evals/ground_truth/` — one file per sample,
named to match the corresponding output file. Each ground-truth file is a flat JSON
object with the expected field values:

```json
{
  "location": "B-rakennus, 2. kerros",
  "fault_description": "Vesiputki vuotaa keittiössä",
  "urgency": "high"
}
```

## Supervisor review (Gate 3)

The PoC outputs the extracted ticket for inspection. In this PoC, the wizard conversation
acts as the review gate: paste or describe the output in the chat and the wizard will help
you assess whether the extraction is correct and refine if needed.

In production, the supervisor receives the ticket JSON, the LLMJudge validation report,
and the transcript, then approves or returns the ticket to the technician for correction.
Only an approved ticket may be transferred to the maintenance management system.
