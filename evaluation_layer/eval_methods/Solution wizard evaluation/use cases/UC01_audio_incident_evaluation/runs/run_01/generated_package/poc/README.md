# Maintenance Fault Reporting via Finnish Voice — Proof of Concept

Generated by GAIK Solution Configuration Wizard V2.

---

## What this PoC does

Field technicians record fault observations as short Finnish voice messages using a mobile
device. This PoC accepts such a recording, runs it through the GAIK pipeline, and produces
a structured `MaintenanceTicket` JSON ready for supervisor review.

**Pipeline steps:**
1. **AudioToStructuredData** — transcribes the Finnish audio with two-pass enhancement
   (`enhanced_transcript=True`), then extracts the structured ticket fields using the
   approved extraction prompt and `MaintenanceTicket` schema.
2. **LLMJudge** — checks the extracted fields against the transcript for hallucinations
   and missing required values; writes a `_validation.json` alongside the ticket.
3. **Human review** — not automated in the PoC. Paste the output into the wizard chat
   to trigger the Gate 3 review loop.

## Prerequisites

- Python 3.11+
- GAIK toolkit: `pip install -r requirements.txt`
- An Azure OpenAI deployment with:
  - A `gpt-4o-transcribe` deployment (for Finnish transcription)
  - A `gpt-5.4` deployment (for structured extraction and LLM judging)
- API credentials in `.env` (see `.env.example`)

## Running the PoC

```bash
# Place your Finnish audio fixture in sample_input/ first, then:
python run_poc.py

# Or specify the audio file directly:
python run_poc.py --input path/to/your_recording.wav
```

Results are written to `output/`.

---

## Input format

Place a single Finnish audio recording in `sample_input/`. Accepted formats: `.wav`, `.mp3`, `.m4a`.

The recording should be a technician describing a facility fault in Finnish, for example:
*"Täällä Matti Korhonen. B-rakennuksen toisessa kerroksessa, huoneessa 214, ilmastointilaite
ei toimi. Vikatilanne on ollut käynnissä tänään aamupäivällä. Kiireellisyys on korkea."*

The pipeline will:
- Transcribe the speech to text (Finnish-enhanced)
- Extract the `MaintenanceTicket` fields
- Save the transcript alongside the JSON output

---

## Expected output

Two files are written to `output/`:

**`<stem>_ticket.json`** — the structured maintenance ticket:
```json
{
  "reporter_name": "Matti Korhonen",
  "asset_identifier": null,
  "location": "B-rakennus, 2. kerros, huone 214",
  "fault_description": "Ilmastointilaite ei toimi",
  "urgency": "high",
  "observation_date": null,
  "observation_time": null,
  "actions_taken": null,
  "uncertain_fields": ["asset_identifier", "observation_date", "observation_time"]
}
```

**`<stem>_validation.json`** — LLMJudge hallucination report:
```json
{
  "hallucination_flags": [],
  "passed": true
}
```

**`<stem>_transcript.txt`** — the Finnish-enhanced transcript.

Required fields (`location`, `fault_description`, `urgency`) must always be present. If a
required field could not be extracted, its value is `null` and its name appears in
`uncertain_fields`.

## Adjusting the PoC

| What to change | Which file |
|---|---|
| Extraction instructions or field rules | `prompts/extraction_requirements.md` |
| Model or temperature | `config.yaml` |
| Schema field types or structure | `schemas/output_schema.py` |
| Evaluation metrics | `evals/run_basic_eval.py` |

If you change `extraction_requirements.md`, the pipeline automatically detects the hash
mismatch on the next run and regenerates the schema from the updated prompt.

---

## Running the basic evaluation

```bash
python evals/run_basic_eval.py
```

Requires ground-truth JSON files in `evals/ground_truth/` matching the field names in
`output_schema.py`. See `evals/run_basic_eval.py` for the expected format. Evaluation
checks: JSON parse success, required-field coverage, semantic fact matching, and
unsupported-value introduction.
