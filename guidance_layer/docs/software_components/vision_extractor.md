# Vision Extractor

Single-pass PDF/image → structured data via a vision LLM. Combines visual document understanding and structured extraction in one API call — no intermediate Markdown parse step.

## When to use

| Use this | Use the regular [`extractor`](extractor.md) |
|---|---|
| Documents with complex layouts, tables that span pages, scanned forms, or hand-marked fields | Clean text/Markdown already exists |
| Cross-document extraction (e.g. a purchase order + multiple bills of materials in one call) | Single document, plain text |
| Row alignment / spatial relationships matter | Extraction is purely textual |
| You want one round-trip instead of parse-then-extract | You already trust your parser output |

## Installation

```bash
pip install "gaik[vision-extract]"
```

Requires credentials for at least one supported provider: OpenAI / Azure OpenAI, Anthropic (Claude / Anthropic Foundry), or Google (Gemini / Vertex AI).

## Quick start

```python
from gaik.software_components.vision_extractor import VisionExtractor

extractor = VisionExtractor(
    model_provider="openai",     # "openai" | "claude" | "google"
    use_azure=True,
    reasoning_effort="low",
)

result = extractor.extract(
    file_paths=["PO.pdf", "BOM1.pdf", "BOM2.pdf"],
    user_requirements="""
        Extract purchase-order header (date, PO number, supplier, contact)
        and line items (item number, description, quantity, price, material number)
        from the PO, aligning each line with the matching BOM via material number.
    """,
    schema_dir="schema_po",      # schema.py + requirements.json persisted here
)

print(result.data)
print(result.documents_processed, result.duration_s, "s")
if result.usage:
    print(result.usage.total_tokens, "tokens")
    print(f"${result.usage.cost_usd:.4f}")
```

All files are sent in a single LLM call so the model sees them together — useful for cross-document alignment that text-based pipelines lose during the parse step.

## Constructor

```python
VisionExtractor(
    api_config=None,                # Optional provider config dict. Skips env loading.
    model_provider="openai",        # "openai" | "claude" | "google"
    model=None,                     # Model/deployment name. None = provider default.
    reasoning_effort="medium",      # "low" | "medium" | "high"
    merge_table=False,              # Instruct model to combine tables split across pages.
    use_azure=True,                 # OpenAI: Azure OpenAI. Claude: Anthropic Foundry.
    vertex_ai=True,                 # Google: True = Vertex AI, False = Gemini direct.
    additional_instructions=None,   # Extra text appended to the user prompt.
    include_verification=False,     # Add confidence_score + confidence_reason per field.
)
```

| Option | Type | Default | Notes |
|---|---|---|---|
| `api_config` | `dict \| None` | `None` | If set, used directly instead of reading env vars. |
| `model_provider` | `"openai" \| "claude" \| "google"` | `"openai"` | |
| `model` | `str \| None` | `None` | E.g. `"gpt-5.4-mini"`, `"gemini-3.1-flash-lite"`. |
| `reasoning_effort` | `"low" \| "medium" \| "high"` | `"medium"` | |
| `merge_table` | `bool` | `False` | |
| `use_azure` | `bool` | `True` | OpenAI: Azure. Claude: Anthropic Foundry. |
| `vertex_ai` | `bool` | `True` | Google only. |
| `additional_instructions` | `str \| None` | `None` | |
| `include_verification` | `bool` | `False` | Wraps each scalar field with confidence metadata. |

## `extract()`

```python
result = extractor.extract(
    file_paths=[...],            # Required. list[str | Path]
    user_requirements="...",     # Required. Natural-language task.
    extraction_model=None,       # Optional pre-built Pydantic model class.
    requirements=None,           # Optional pre-built ExtractionRequirements.
    schema_dir=None,             # Optional directory for schema persistence.
)
```

Schema resolution order:

1. If both `extraction_model` and `requirements` are passed → used directly.
2. Else if `schema_dir` points to existing `schema.py` + `requirements.json` → loaded.
3. Otherwise → generated by [`SchemaGenerator`](extractor.md) and (when `schema_dir` is set) saved.

Returns a `VisionExtractionResult` dataclass:

| Field | Type | Description |
|---|---|---|
| `data` | `dict` | Extracted, schema-validated structured data. |
| `verification` | `dict \| None` | Per-field `{confidence_score, confidence_reason}` when `include_verification=True`. |
| `usage` | `UsageRecord \| None` | Provider-agnostic token usage + cost record. |
| `duration_s` | `float` | LLM call wall time. |
| `model` | `str` | Effective model/deployment used. |
| `documents_processed` | `int` | Number of files sent in the call. |

## Supported file types

`.pdf .png .jpg .jpeg .gif .webp .tiff .tif .bmp`

## Per-field verification

When `include_verification=True`, the model is asked to produce `{value, confidence_score, confidence_reason}` for every scalar field (and per-row for list-of-rows). The unwrapped data is returned in `result.data`; the metadata is separated into `result.verification` so downstream code can render either view without double-keying.

Useful for human-in-the-loop QA, dashboards, and audit trails where extractors must justify themselves.
