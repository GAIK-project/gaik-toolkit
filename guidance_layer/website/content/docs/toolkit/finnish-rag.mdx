## What it is

`FinnishTextProcessor` is a small preprocessing layer that lemmatizes Finnish
text and (optionally) splits compound words. It plugs straight into
[`PgVectorStore`](/toolkit/software-components#pgvectorstore) via the
``text_processor`` constructor argument so hybrid full-text + vector search
matches inflected forms ("kissan", "kissoilla" → "kissa") and compound parts
("kerrostalo" → "kerros" + "talo").

## Why this exists

The default `pg_vector_store` FTS configuration is `'simple'`. That means
"kerrostalollekohan" stays as one opaque token in the tsvector, and a search
for "kerrostalo" misses it. Finnish has rich morphology and productive
compounding — the mismatch between query forms and stored forms wrecks recall.

`FinnishTextProcessor` solves this in pure Python before Postgres ever sees
the text:

1. On **ingest**, content is lemmatized into a separate `content_lemmatized`
   column. The `text_search` tsvector is built from those lemmas.
2. On **query**, the search text is lemmatized through the same processor
   before being handed to `websearch_to_tsquery`.

Both inflected user queries and compound-rich documents now match.

## Backends

When `backend="auto"` (default), the processor tries these in order and uses
the first that imports cleanly:

| Backend | Morphology | Compound splitting | Install |
| --- | --- | --- | --- |
| `voikko` | Best (libvoikko + suomi-malaga) | ✅ | `pip install gaik[finnish-rag-voikko]` + `apt install libvoikko1` |
| `spacy` | Solid (`fi_core_news_md`/`lg`) | ❌ | `pip install gaik[finnish-rag]` + `python -m spacy download fi_core_news_md` |
| `uralic` | Pure-Python via UralicNLP | ❌ | `pip install gaik[finnish-rag]` |
| `simple` | None — regex tokenizer + lowercase | ❌ | Always available (last-resort fallback) |

## Quick start

```python
from gaik.software_components.RAG.finnish_text_processor import FinnishTextProcessor
from gaik.software_components.RAG.pg_vector_store import PgVectorStore

processor = FinnishTextProcessor(backend="auto")
print(processor.lemmatize("kerrostalon kissoilla"))
# → ["kerros", "talo", "kissa"]   (Voikko)
# → ["kerrostalo", "kissa"]       (spaCy / UralicNLP)

with PgVectorStore(
    "postgresql://postgres:postgres@localhost/mydb",
    text_processor=processor,
) as store:
    store.setup()
    store.add(documents, embeddings)
    results = store.search_hybrid(
        query_embedding=q_vec,
        query_text="kerrostalon kissoilla",
        top_k=5,
    )
```

The integration is opt-in — leaving `text_processor=None` keeps the legacy
behaviour byte-for-byte.

## Standalone usage

The processor is also useful outside `PgVectorStore`. Three public methods:

```python
processor.lemmatize("Kissoilla on neljä jalkaa")
# → ["kissa", "olla", "neljä", "jalka"]

processor.to_tsvector_text("Kissoilla on neljä jalkaa")
# → "kissa olla neljä jalka"      # ready for to_tsvector('simple', ...)

processor.expand_query("kerrostalon kissalla")
# → "kerros talo kissa"           # ready for websearch_to_tsquery
```

## Stopwords

A small built-in Finnish stopword list filters out function words ("ja",
"tai", "että", …) before lemmatization. Override per-backend by passing a
custom set; the default is conservative on purpose — aggressive stopword
removal hurts retrieval.

## Future direction

A separate `gaik-pgvoikko` Docker image with `dict_voikko` baked into
Postgres is on the roadmap when production deployments need Postgres-native
morphology rather than a Python preprocessing pass. Until then, the `voikko`
Python backend covers the same morphology with a small extra Python step.
