## Current Solution Development Stage

- **Current phase is early ideation with an existing non-AI system:** The company already has a functioning interactive system that maps sensor-based movement to sound and lighting using statistical and manual methods, but the AI component has not yet been built and is still being discussed conceptually (framerate.mp3).
- **No machine learning is currently in use:** The speaker explicitly stated that “there's actually no machine learning” in the present system and confirmed that it is not a generative AI model, which places AI development before prototyping in practical terms (framerate.mp3).
- **A clear first AI use case has been identified:** The main near-term AI objective is to take speech or text input describing desired music, convert it to text if needed, and match it against audio metadata in a database so the most relevant pre-generated music can be selected (framerate.mp3).
- **The movement-to-sound pipeline is already functional without AI:** The current body or movement mapping works through statistical analysis such as acceleration, velocity, and location, and this is considered effective and responsive enough for real-time use at present (framerate.mp3).
- **Low-latency constraints shape AI readiness:** The team is cautious about using generative AI for movement-to-sound control because latency above roughly 100 milliseconds was described as harmful to the user experience, and advisors noted that such models would likely increase delay and hardware demands (framerate.mp3).
- **Data readiness is incomplete:** The company does not yet have the target audio database or metadata set in place, and the speaker said they still need to determine the size, diversity, and generation process for the musical material that would support matching (framerate.mp3).
- **Technical direction for a prototype was suggested:** Advisors proposed starting with speech-to-text using OpenAI speech models, generating or extracting metadata for a limited set of audio files, and then testing either direct LLM matching for small collections or embedding-based retrieval with cosine similarity for larger sets (framerate.mp3).
- **What exists versus what still needs development is clearly separated:** The real-time interactive artwork infrastructure exists, but the AI-related pieces that still need development include speech recognition integration, metadata generation or extraction, audio database construction, retrieval logic, and user testing of match quality (framerate.mp3).
- **The company is looking for practical implementation guidance rather than outsourced build work:** The speaker asked for suggestions on speech recognition, embeddings, and next technical steps, while the advisors clarified that this use case is considered simple enough for the company to build itself with advisory follow-up rather than a formal proof-of-concept service (framerate.mp3).
- **The immediate aim is proof through user response:** The stated ultimate goal is to test the system with people and see whether the returned music feels close enough to the request, which shows the next milestone is experiential validation rather than commercial deployment (framerate.mp3).
